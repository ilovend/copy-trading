# 仓位复制页 · 功能设计（v0.1）

> 目标：把「仓位监控」拿到的实时信号，按自定义比例在**另一个账户**执行。
> 状态：设计稿，未实现。日期 2026-11-11。

---

## 1. 目标与非目标

**要做的**

- 接收监控页产生的成交事件（开 / 加 / 减 / 平），在执行账户下对应订单
- 支持三种比例模型，可按单个带单员配置
- 执行前有一整套风控拦截，宁可漏单不可失控
- 先跑「影子模式」：真实计算、但不发单，用于验证

**不做的（至少这一版）**

- 不做反向跟单（以后可作为开关）
- 不做跨交易所执行
- 不做自动选币 / 自动调仓
- 不碰官方跟单账户本身（它是信号源，只读）

---

## 2. 前置条件

| 项 | 要求 |
|---|---|
| 执行账户 | 建议新开子账户，与官方跟单账户隔离 |
| API 权限 | 合约交易 ✅、读取 ✅、提现 ❌、IP 白名单 ✅ |
| 资金 | 先放小额（如 50–100 U），跑通再加大 |
| 网络 | 与监控同一台机器即可；下单走 `fapi.binance.com` |

> API Key 只存在本机 `.env`，程序不落盘明文到日志。

---

## 3. 核心链路

```
跟单组合成交（WS 事件，~100ms）
        │
        ▼
  事件归一化  {symbol, side, ps, qty, price, rp, orderId, T}
        │
        ▼
  去重 + 陈旧判断（>3s 丢弃）
        │
        ▼
  比例换算 → 目标数量（按 stepSize 取整）
        │
        ▼
  风控闸门（单笔/单币/敞口/日亏/滑点）
        │
        ├─ 影子模式：只写日志 + 推送「本应下单」
        └─ 实盘模式：下单 → 成交回报 → 对账
```

关键认知：**镜像成交的数量已经包含官方跟单比例**，我们只需要乘一个系数，
不需要去查带单员的原始仓位。这让实现简单很多。

## 5. 区块与功能

### 5.1 执行账户

| 功能 | 说明 |
|---|---|
| 填 Key/Secret | 默认遮挡，可点「显示」 |
| 测试连接 | 调 `/fapi/v2/account`，显示权益、可用、持仓数 |
| 保存 | 写入 `.env`（`EXEC_API_KEY` / `EXEC_API_SECRET`） |
| 杠杆 / 保证金模式 | 跟随带单员、固定值（1–20x）、逐仓或全仓 |

### 5.2 比例规则

每个带单员一行，可独立覆盖全局默认：

- 模式：净值比、固定倍数、固定保证金
- 系数 k
- 单笔上限（U）
- 单币仓位上限（%）
- 开关（临时停跟某个人，不影响监控）

### 5.3 风控

全局生效，任何一条触发就拒绝该笔并推送告警。

### 5.4 运行状态

模式（影子、实盘）、账户权益、可用余额、今日盈亏、已复制笔数、最近信号。

### 5.5 操作

- **开始复制 / 暂停**（不停止监控）
- **全部平仓**（紧急，需二次确认）
- **导出今日执行记录**

## 7. 三种比例模型

设：镜像成交数量 `q_c`、成交价 `p`、镜像组合保证金余额 `E_c`、执行账户权益 `E_x`。

**① 净值比（默认，最贴近"按比例跟单"）**

```
q_x = q_c × (E_x / E_c) × k
```

例：`q_c=29`、`E_c=100`、`E_x=500`、`k=1` → `q_x=145` 张。
执行账户是镜像账户的 5 倍，就放大 5 倍。

**② 固定倍数（最直观）**

```
q_x = q_c × k
```

适合"我就想放大 3 倍"，不关心两边净值。

**③ 固定保证金（最可控）**

```
名义 = margin_per_trade × leverage
q_x  = 名义 / p
```

不随净值漂移，每笔风险固定。适合资金少、想严格控制单笔亏损。

> 三种都要再过一遍「单笔上限」，取 `min()`。

## 8. 执行流程

```
收到事件
  ├─ 去重：key = orderId + tradeTime + lastFilledQty
  ├─ 年龄：now - T > max_signal_age → 丢弃并记 skipped
  ├─ 分类：rp == 0 → 开/加；rp != 0 → 平/减
  ├─ 计算 q_x → 按 stepSize 向下取整 → 小于 minNotional 则跳过
  ├─ 风控检查（5 条）
  ├─ 影子：写 intent，推 Telegram「本应：BUY 58 ADA @0.173」
  └─ 实盘：
       ├─ 平/减：reduceOnly=true，数量 = min(q_x, 当前持仓)
       ├─ 开/加：设定杠杆 → 下单（限价 p×(1±滑点)）
       ├─ 超时未成交：撤单（或转市价，可配）
       └─ 成交回报 → 写 fill → 对账
```

**反手**（多转空）：先 `reduceOnly` 平掉，再开新仓，中间不做净额对冲。
默认关闭，防止意外。

---

### 8.1 平仓：限价优先，超时转市价

目标：常态拿更好的价格，极端行情也能保证走掉。

```
qty_need = min(q_x, 当前持仓)

if close_order_type == market:
    市价 reduceOnly 平掉 qty_need
else:
    挂 reduceOnly 限价单
        多头平仓 → 卖出，价格 = 卖一价（或 mark × (1 - offset)）
        空头平仓 → 买入，价格 = 买一价（或 mark × (1 + offset)）
    每 500ms 检查一次订单状态（也可复用 WS 的订单回报）
    全部成交 → 完成
    超时 close_limit_timeout_s（默认 5s）：
        撤单
        剩余数量 → 市价 reduceOnly
        记录「走了 fallback」
```

状态机：

```
SENT ──部分成交──> PARTIAL ──成交完──> FILLED
  │                    │
  └────超时────────────┴──> CANCEL ──> MARKET ──> FILLED
```

要点：

- **超时不要设太长**（3–5 秒）。太长等于放弃平仓，行情跑掉的风险比滑点更大
- 限价挂在**对手价**，成交率最高，绝大多数情况不会触发 fallback
- fallback 也要记录滑点（市价成交价 vs 信号价），用于事后评估这条策略是否划算
- 部分成交同样走「撤剩余 → 市价补齐」

### 8.2 插针行情专项（重要）

如果跟的带单员主要做插针/急拉急砸，平仓的**成交确定性**比价格更重要。

**问题**

- 插针时盘口极薄，市价单可能穿好多档，成交在很离谱的位置
- GTC 限价单在插针里大概率挂不掉（价格瞬间弹回）
- 等 5 秒再转市价，可能已经错过最佳离场点

**对策一：IOC 限价（推荐主路径）**

用 `timeInForce=IOC` 的限价单，价格设在「可接受的最差价格」：

```
多头平仓：SELL, price = mark × (1 - max_slippage_pct), timeInForce=IOC
空头平仓：BUY,  price = mark × (1 + max_slippage_pct), timeInForce=IOC
```

语义是「**要么在滑点上限内立刻成交，要么立刻失败**」，不会挂在那边等。
比市价安全（有价格上限），比 GTC 限价可靠（不会挂死）。

成交失败时按 `ioc_fallback` 处理：

| 选项 | 行为 | 适用 |
|---|---|---|
| `retry_wider` | 放宽 0.2% 再试一次 IOC | 默认，给一次机会 |
| `market` | 直接市价 | 确定要离场，接受滑点 |
| `stop_loss` | 交给交易所侧止损单 | 程序不赌，交给硬止损 |

**对策二：交易所侧保护止损（保命）**

开仓成交后，立刻在交易所挂一张 `STOP_MARKET + reduceOnly` 的止损单：

```
多头：STOP_MARKET, stopPrice = entry × (1 - protective_stop_pct), closePosition=true
空头：STOP_MARKET, stopPrice = entry × (1 + protective_stop_pct), closePosition=true
```

这张单**不依赖本程序**——就算程序崩了、断网了、cookie 过期了，插针打穿也会被交易所强制平掉。
跟单信号平仓成功后再把它撤掉。

**对策三：仓位与延迟**

- 单笔 5–10 U，插针最坏情况也亏得起
- 平仓走 IOC，不做「挂 5 秒再市价」的等待（插针场景下等待=错过）
- 所以 `close_order_type` 在插针模式下默认用 `ioc_limit`，而不是 `limit_then_market`

**必须诚实面对的一点**

插针策略的收益来自极快的进出。我们的链路是「带单员成交 → 官方镜像 → WS 推送 → 我们再下单」，
正常约 100ms，插针时可能更慢。**滑点很可能吃掉策略的大部分收益。**

所以影子模式必须额外量一个数：**信号价 vs 当时盘口可成交价**（用 `/fapi/v1/depth` 算），
如果平均滑点 > 策略预期单笔收益，这套就不值得做。这个数据不需要花一分钱就能先测出来。

## 9. 精度与交易规则
| 项 | 处理 |
|---|---|
| `stepSize` | 向下取整，宁可少一点 |
| `minNotional` | 小于则跳过并提示 |
| `maxQty` | 超过则截断 |
| 价格精度 `tickSize` | 按交易所规则对齐 |
| 杠杆 | 下单前 `POST /fapi/v1/leverage` |
| 保证金模式 | 首次切换需无持仓，失败则记录 |

## 10. 风控与熔断

| 规则 | 触发动作 |
|---|---|
| 单笔名义 > 上限 | 拒绝，推送 |
| 单币仓位 > 上限 | 拒绝，推送 |
| 总敞口 > 上限 | 拒绝，推送 |
| 日亏 > 上限 | 停止复制，推警报 |
| 连续下单失败 ≥ N | 停止复制，推警报 |
| 信号年龄 > N 秒 | 跳过，记录 |
| 账户权益 < 阈值 | 停止复制 |
| API 报错 -2019（保证金不足） | 跳过该笔，不重试 |

所有拒绝都写 `rejects` 日志，带原因码，方便复盘。

## 11. 对账

每 30 秒一次：

1. 拉执行账户持仓
2. 与「按信号累计出的目标持仓」比较
3. 偏差 > 阈值：
   - 默认只告警
   - 可选自动修正（需显式开启）
4. 记录 `reconcile` 表：时间、币种、目标、实际、偏差

**孤儿仓**（有仓无信号）：只告警，不自动平，避免误杀。

---

## 12. 影子模式（第一版必须先做）

- 全流程照跑：换算、取整、风控、算滑点
- **不调用下单接口**
- 输出：`intent` 记录 + Telegram 消息 + 收盘统计
- 跑满 1 天，看三个数：
  1. 取整误差（目标 vs 理论）
  2. 理论成交价 vs 当时盘口（估算滑点）
  3. 被风控拒绝的比例

这三个数达标，才开实盘。

### 17.1 净值比的实际算例（用当前账户）

星辰社区-海：镜像组合保证金余额 `E_c = 100.24 U`，执行子账户 `E_x = 50 U`。

| 步骤 | 计算 | 结果 |
|---|---|---|
| 镜像成交 | 29 张 ADA @ 0.1731 | 名义 5.02 U |
| 资金比例 | 50 ÷ 100.24 | 0.499 |
| 目标数量 | 29 × 0.499 | 14.5 张 |
| 按 stepSize 取整 | floor(14.5 / 1) × 1 | **14 张** |
| 名义校验 | 14 × 0.1731 | 2.42 U ✅ |

执行账户权益涨到 80 U 后，同一信号自动变成 23 张，不用改配置。

### 17.2 执行账户怎么准备

**正式实盘用主账户**（子账户只适合测试）：

1. 主账户创建 API Key，权限：合约交易 ✅、读取 ✅、**提现 ❌**
2. 绑定 IP 白名单（本机出口 IP；换节点要同步更新）
3. 把资金放在主账户的**合约钱包**（不是现货钱包）
4. 首次实盘前用「测试连接」确认权益能读到

**为什么不建议子账户**：

| 限制 | 影响 |
|---|---|
| 最高 5 倍杠杆 | 想用 20x 直接报 `-4421` |
| 不支持官方跟单 | 只能当执行端，不能当镜像源 |
| 多一层资金划转 | 容易忘记转账，导致下单被拒 |

子账户唯一的好处是隔离资金，代价是上面这些限制。除非你明确需要隔离，否则用主账户。

### 19.4 最小名义处理规则（v0.4）

**开仓**：按比例算出的名义 < 5U 时，补到 5U 下单，日志标 `[补到最小名义]`。
可在 GUI 复制页关掉这个开关。

**平仓**分三种情况：

| 情况 | 处理 |
|---|---|
| 镜像整仓平（100%） | 执行端整仓平，不受最小名义限制 |
| 部分平仓 ≥ 5U | 按比例平 |
| 部分平仓 < 5U，且总仓位 < 10U | 仓位太碎，**整仓平掉** |
| 部分平仓 < 5U，且总仓位 ≥ 10U | 跳过（`too_small_partial`），等下一次更大减仓 |

实测：

```
镜像开 10 张 → 比例 5 张(0.87U) → 补到 29 张(5.07U)  [补到最小名义]
镜像平 5 张(50%) → 目标 15 张(2.62U) < 5U，仓位仅 5.07U → 整仓平 29 张
```

> 补最小名义会让小额信号的实际敞口大于比例值；
> 单币上限（25%）和总敞口上限（40U）仍然生效，不会无限放大。

## 20. 对齐币安官方口径（v0.5）

查了官方 FAQ 和跟单设置说明，官方两种模式的定义是：

| 模式 | 官方做法 |
|---|---|
| 固定金额 | 每笔投入**固定保证金**（`costPerOrder`），名义 = 保证金 × 杠杆 |
| 固定比例 | 按你设定的**跟单总投资额**等比复制带单员仓位 |
| 最小下单额 | 低于交易对最小名义时**直接跳过**（官方承认这是执行损耗之一） |
| 滑点上限 | BTC/ETH 默认 0.3–0.5%，其他币默认 1.5%，可调至 3% |
| 跟单金额 | 常见最低 10 USDT，带单员可上调 |

### 20.1 本工具对照

| 维度 | 官方 | 本工具 | 状态 |
|---|---|---|---|
| 固定金额 | 固定保证金 × 杠杆 | `margin_per_trade × leverage` | ✅ 一致 |
| 固定比例 | 分母是跟单总投资额 | 分母改用 `netCopyAmount`（净投入） | ✅ 已改 |
| 低于最小名义 | 跳过 | 补到 5U（可关） | ⚠️ 有意偏离 |
| 滑点上限 | 分币种 | BTC/ETH 0.5%，其他 1.5% | ✅ 已改 |
| 组合止损 | 支持 | 预留 | ⏳ |
| 单仓 TP/SL | 支持 | 预留 | ⏳ |

**为什么偏离「跳过」**：50U 本金跟 100–200U 的组合，按比例常常不足 5U。
照官方跳过，绝大多数信号都会丢，等于没跟。补到 5U 是折中，
代价是小额信号被放大（上限 = 1/比例，当前配置下 2–4 倍）。

### 20.2 另一个官方限制

币安明确：**子账户一般不支持官方跟单**。
执行账户可以用子账户做合约交易，但不能指望在子账户里开官方跟单——两件事互不影响。


### 19.5 部分平仓聚合（v0.6）

问题：镜像高频小单减仓时，每笔按比例只有 0.3–2U，低于 5U 最小名义，
一笔笔跳过会导致执行端仓位越堆越大（随后触发单币上限）。

做法：维护「待减仓累计」，每笔小减仓先累加，累计名义 ≥5U 时一次性平掉；
镜像整仓平时直接全平，不留残仓。

实测（镜像开 100，连续 5 张减仓）：

```
ACCUM  累计减仓 0.46U / 需 5U
ACCUM  累计减仓 2.01U / 需 5U
ACCUM  累计减仓 4.57U / 需 5U
CLOSE  target=31  notional=5.41U  hold=22   ← 攒够了一次平
...
CLOSE  target=22  hold=0（镜像整仓平）
```

## 21. 持仓模式（单向 / 双向）

币安的持仓模式是**账户级设置**，只能在合约界面齿轮里或通过 API 切换，程序改不了
（有持仓时切换会被拒绝）。

| 模式 | 开多 | 平多 | 备注 |
|---|---|---|---|
| 单向（One-way） | `BUY` | `SELL` + `reduceOnly` | 同一币种只能一个方向 |
| 双向（Hedge） | `BUY` + `positionSide=LONG` | `SELL` + `positionSide=LONG` | **不能带 reduceOnly** |

本工具的处理：

- 启动或首次下单前调用 `GET /fapi/v1/positionSide/dual` 自动识别
- 双向模式自动给订单加 `positionSide`，并去掉 `reduceOnly`
- 「测试连接」会显示当前模式：
  `账户持仓模式：双向持仓（下单会自动带 positionSide）`
- 查询失败时按单向处理，并在日志里写明原因

切换方式：币安合约界面右上角齿轮 → 持仓模式 → 单向 / 双向。

### 23.1 主账户注意事项：杠杆是全局设置

### 19.6 最小名义要留缓冲（实战反馈）

用户实测：在币安界面上，名义正好 **5.00U** 时经常报"小于最小名义"，
必须填到 5.01 / 5.02 才能下单。

原因：币安按「价格 × 数量」的浮点值比较，5.00 很容易算成 4.9999…，
再加上按 tick/step 取整的误差，正好卡边界就会被拒。

处理：

- 新增配置 `min_notional_buffer_pct`，默认 **1%**
- 有效最小名义 = `max(交易所 minNotional, 配置值) × (1 + 1%)`
- 5U 的最小名义，程序实际按 **5.05U** 起算
- 补名义时向上取整到步长，实测 16 张 × 0.3162 = 5.06U
