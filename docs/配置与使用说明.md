# 配置与使用说明

> 适用版本：v1.0.0

> 币安跟单监听器：自动发现你所有跟单组合，逐个建立 WebSocket，成交落地 Telegram。
> 项目路径：`E:\ilovendProject\copy-trading`

---

## 一、它做什么

```
币安跟单引擎镜像成交 → 你的跟单组合账户
        ↓  WebSocket 实时推送（每个组合一条）
    本机监听器（bot/listen_copy.py）
        ↓  格式化 + 去重 + 落盘
   Telegram（手机秒收）
```

- 启动时自动调 `copy-portfolio/detail-list` 拿到你**全部**跟单组合和对应带单员
- 每个组合一个独立 `listenKey` + WebSocket，互不影响
- 每 25 分钟自动续期 `listenKey`，断线指数退避重连
- 每笔成交写 `bot/data/`，同时推 Telegram
- 网页会话过期会发告警

## 四、`.env` 参数

文件位置：`E:\ilovendProject\copy-trading\.env`
已被 `.gitignore` 忽略，**不要提交、不要发群里**。

### 参数总表

| 参数 | 必填 | 默认 | 作用 |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | ✅ | 无 | 机器人 token，推送的凭据 |
| `TELEGRAM_CHAT_ID` | ✅ | 无 | 推给谁（你的 chat id） |
| `TELEGRAM_PROXY` | ⬜ | 空 | 访问 Telegram 的本地代理，留空直连 |
| `COPY_PORTFOLIO_ID` | ⬜ | 空 | 兜底组合 ID，自动发现失败时才用 |
| `WATCH_NICKNAMES` | ⬜ | 空 | 只监听名字包含关键词的带单员，逗号分隔 |
| `WATCH_LEADS` | ⬜ | 空 | 按带单员 ID 精确筛选 |
| `WATCH_PORTFOLIOS` | ⬜ | 空 | 按你的组合 ID 精确筛选 |
| `BINANCE_COOKIE` | ⬜ | 空 | 网页登录态 cookie（与下一项配对） |
| `BINANCE_CSRFTOKEN` | ⬜ | 空 | 与 cookie 配对的 csrftoken |
| `BINANCE_UA` | ⬜ | 空 | 自定义 UA，一般不用填 |

> **必填只有前两项。** 中间两项按需。最后三项是"会话直填"的备选方案（见第五节），
> 填了它们就会覆盖 `session.json`。

---

### 4.1 `TELEGRAM_BOT_TOKEN`（必填）

获取步骤：

1. Telegram 搜索 **@BotFather**
2. 发送 `/newbot`
3. 按提示设置显示名和用户名（用户名必须以 `bot` 结尾）
4. BotFather 返回一串 `123456789:AAH...`，这就是 token（46 位左右）

```
TELEGRAM_BOT_TOKEN=123456789:AAHxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

注意事项：

- **建完必须主动给机器人发一句话**（随便发），否则机器人不能主动私聊你
- token 泄露等于别人可以冒充你的机器人发消息，泄露后去 BotFather `/revoke` 重置

---

### 4.2 `TELEGRAM_CHAT_ID`（必填）

两种获取方式，任选其一：

**方式 A（推荐）**

1. Telegram 搜索 **@userinfobot**
2. 点 Start / 发任意消息
3. 它回复的 `Id: 9279871968` 就是你的 chat id

**方式 B**

浏览器打开：

```
https://api.telegram.org/bot<你的TOKEN>/getUpdates
```

在返回的 JSON 里找 `"chat":{"id":123456789,...}`。

```
TELEGRAM_CHAT_ID=9279871968
```

> 群组也支持，群 id 一般是负数（如 `-1001234567890`），需先把机器人拉进群。

---

### 4.3 `TELEGRAM_PROXY`（可选）

国内直连 `api.telegram.org` 经常超时，填本地代理端口能显著降低推送延迟。

```
TELEGRAM_PROXY=http://127.0.0.1:7890
```

- 支持 `http://` 和 `https://`
- Clash 默认 `7890`，V2Ray 常见 `10809`
- **留空 = 直连**，如果你的网络本来就能通 Telegram，保持空即可

判断标准：启动后能收到「🚀 跟单监听已启动」就说明通了。

---

### 4.4 `COPY_PORTFOLIO_ID`（可选，兜底）

正常情况**不用填**。程序启动时会自动拉取全部跟单组合。

只有在自动发现失败（接口改版、返回异常）时，才会退化成只监听这一个组合。

怎么找：打开跟单管理页，任意一条 `copy-portfolio` 请求的 `--data-raw` 里都有：

```json
{"copyTradeType":"COPY","portfolioId":"5307462232747617537"}
```

19 位纯数字，填进去即可。

---

### 4.5 `BINANCE_COOKIE` + `BINANCE_CSRFTOKEN`（可选，替代 session.json）

默认不用填：登录态推荐由 `bot/update_session.py` 自动生成到 `session.json`（见第五节）。
如果你更想把配置集中在一个 `.env` 里，就填这两项：

```
BINANCE_COOKIE=aws-waf-token=...; bnc-uuid=...; logined=y; ...
BINANCE_CSRFTOKEN=e8bfb33b02ef2fddf9bf5151ac80dbbd
```

要点：

- **两项必须同时填。** 实测只填 cookie 会返回
  `401 {"code":"100002002","message":"请求失败，请检查是否已登录！"}`，
  因为请求头必须带 `csrftoken`，而它不在 cookie 串里。
- 值**原样粘贴，不要加引号**（引号会被当成值的一部分）。
- cookie 一般 1400+ 字符，手工复制极易漏字符；能用脚本就别手抄。
- 填了这两项后，**优先级高于** `session.json`。

### 4.6 `BINANCE_UA`（可选）

自定义 User-Agent。留空时依次取 `session.json` 的 `user-agent`，再退回内置 Edge UA。

### 4.7 只监听部分带单员（`WATCH_*`）

默认监听**全部**。三项任意填一个，就进入筛选模式；命中规则是"满足任意一条即可"：

| 变量 | 匹配方式 |
|---|---|
| `WATCH_NICKNAMES` | 名字**包含**关键词（不区分大小写） |
| `WATCH_LEADS` | 带单员 ID **完全相等** |
| `WATCH_PORTFOLIOS` | 你的组合 ID **完全相等** |

多个值用英文逗号分隔。

```ini
# 只要这两个人
WATCH_NICKNAMES=玄冥二老,星辰社区-海

# 只要"星辰社区"系列（会命中 3 个）
WATCH_NICKNAMES=星辰社区

# 按带单员 ID 精确指定
WATCH_LEADS=4908633203782592768,5131925334830383361
```

**先验证再启动**（不会建立连接）：

```bat
python bot\listen_copy.py --dry-run
```

输出里看这行：

```
watching 2/4: 玄冥二老, 星辰社区-海
```

**临时只看某个人**，不改 `.env`：

```bat
python bot\listen_copy.py --only 玄冥二老
python bot\listen_copy.py --only 星辰社区
```

`--only` 与三个 `WATCH_*` 是并集关系。写了但没匹配上的词会在日志里告警，并列出当前可选的名字。

> 同一个组合不要同时跑多个实例，后启动的会把前一个的 `listenKey` 踢掉，导致反复重连。

## 五、登录态（配在哪）

**答案：不放 `.env`，放在 `session.json`。**
（除非你用了 4.5 的两个变量，那样 `.env` 优先。）

为什么单独放文件：一份有效登录态由 `cookie` + `csrftoken` + `bnc-uuid` + `fvideo-id/token`
等多个字段组成，cookie 本身就 1400+ 字符，塞进 `.env` 手抄必错；而且需要被校验、会被频繁替换。

WebSocket 的 `listenKey` 必须用这份登录态去换，所以它是必需的。

### 推荐方式：一条命令生成

**推荐：在 GUI 里点「更新登录态」**，弹窗会一步步提示，并且校验你粘的内容。

手动步骤（弹窗里也有）：

1. 浏览器登录币安，打开
   `https://www.binance.com/zh-CN/copy-trading/copy-management`
2. 按 `F12` → **Network** → `F5` 刷新
3. 过滤框输入 **`bapi`**，任意点开一条接口请求
   （例如 `.../usertask/challenge/list`，任何带登录态的 `bapi` 请求都可以）
4. 右键它 → **Copy** → **Copy as cURL (bash)**
5. 回到 GUI 弹窗，粘贴 → 点「开始更新」

> 一定要注意：复制的是 `bapi/...` 接口请求，不是页面地址、不是 `.js` 文件。
> 弹窗会检查内容里有没有 `bapi` 和 `csrftoken`，不符合直接拦下，不会写坏 `session.json`。

命令行等价操作（内容在剪贴板时）：

```bat
python bot\update_session.py --clipboard
```

看到下面这样就成了：

```
校验：✅ 有效，非零资产 N 个
已写入 ...\session.json
```

### 想确认字段 / 手动填

`session.json` 结构（值已省略）：

```json
{
  "cookie": "aws-waf-token=...; bnc-uuid=...; logined=y; ...",
  "csrftoken": "e8bf...",
  "bnc-uuid": "0653...",
  "fvideo-id": "...",
  "fvideo-token": "...",
  "x-passthrough-token": "...",
  "device-info": "...",
  "user-agent": "Mozilla/5.0 ...",
  "portfolioId": "5307462232747617537"
}
```

- **最少需要 `cookie` + `csrftoken`**，缺一个就是 401。
- `user-agent` 建议保留，和抓包时一致，降低风控概率。
- `portfolioId` 只作兜底，可留空。

### 有效期与更新

- 一般 **2–3 天**过期
- 过期后监听器会重连失败，并推一条「⚠️ 监听中断」
- 重新执行上面第 5 步即可；**监听器会自动检测文件变化并重载**（最多 25 分钟生效，想立刻生效就重启）

> `session.json` 也能被 `.gitignore` 忽略，但它等同于你的登录态，比 API Key 更敏感。

## 六、启动

### 桌面控制台（推荐）

```bat
gui\启动.bat
```

或：

```bat
python gui\app.py
```

窗口分三个标签页：

| 标签页 | 内容 | 状态 |
|---|---|---|
| **仓位监控** | 跟单组合列表、启停监听、运行状态、实时日志 | 可用 |
| **仓位复制** | 执行账户、比例模式、风控参数；影子模式可运行 | 影子可用（不下单） |
| **仓位推送** | Telegram 配置 + 测试发送；QQ / 微信 / 钉钉 / Webhook 占位 | Telegram 可用 |
| **自动跟单** | 收藏带单员的名额监控、自动加入、跟单参数 | 可用（默认只提示） |

> 「仓位复制」页的参数会随比例模式自动启用/禁用：
> 净值比和固定倍数只用「系数 k」；固定保证金只用「每笔保证金 + 杠杆」。
> 灰色框表示当前模式不参与计算，填了也不生效。

**并发规则**

| 同时运行 | 可以？ | 说明 |
|---|---|---|
| 仓位监控 + 自动跟单 | ✅ | 一个走 WebSocket，一个走 REST |
| 影子复制 + 自动跟单 | ✅ | 同上 |
| 仓位监控 + 影子复制 | ❌ | 都要给同一组合申请 listenKey，会互相踢下线 |

三个任务各自独立启停，右侧状态栏分别显示「监控 / 影子复制 / 自动跟单」是否在运行，
日志每行前面带 `[监控]` `[影子]` `[跟单]` 前缀，混在一起也能分清。

仓位监控页布局：

| 区域 | 用途 |
|---|---|
| 列表 | 带单员 / 带单员ID / 我的组合ID / 保证金余额 / **监控** / **复制** |
| 按钮栏 | 刷新列表、启动、停止、更新登录态、打开数据目录 |
| 右侧 | 运行状态（监控 / 影子复制 / 自动跟单 / 推送 / 代理 / 登录态） |
| 下方 | 实时日志，成交高亮 |

**监控 / 复制两列直接点单元格切换**（✓ / ○）：

- 「监控」勾选 = 盯这个人的成交并推送
- 「复制」勾选 = 同时把成交按比例算单（影子模式）
- 勾「复制」会自动把「监控」一起勾上

按钮栏右侧会实时提示将要启动什么，例如：

```
将启动：监控 + 影子复制（复制 2/4）
```

点「启动」后由程序自动决定跑哪个进程：

| 勾选情况 | 实际启动 |
|---|---|
| 只勾了监控 | `listen_copy.py`（只监听） |
| 有任意复制 | `copy_run.py`（监听 + 影子复制，一份进程搞定） |

所以**不需要先去监控页开监听、再去复制页开复制**——那本来就是重复启动。

**第一次用（新手三步）**

1. 切到「仓位推送」→ 填 Bot Token 和 Chat ID → 点「测试发送」→ 手机收到就点「保存」
2. 回「仓位监控」→ 点「更新登录态」，按提示从浏览器复制 cURL
3. 列表里点「监控 / 复制」勾选 → 点「启动」

> 改完推送配置后，正在运行的监听器需要重启才生效。

### 自动跟单页

用于「名额满了先排队，出现空位自动加入」的场景：

1. 点「刷新收藏」——只列出你收藏的带单员
2. 在左侧多选要监控的人
3. 右侧填跟单参数：投资金额、跟单模式（固定比例/固定金额）、总止损、止盈、止损、保证金模式、杠杆
4. 需要真下单才勾选「实际下单」，否则只推 Telegram 不真的加入
5. 点「启动监控」

程序每 3 秒拉一次收藏列表，发现 `currentCopyCount < maxCopyCount` 就按参数加入。
加入成功/失败都会推 Telegram，并写明原因。

> 实盘加入会真实扣款，界面上有二次确认。建议先不勾「实际下单」跑一轮，确认能正常发现名额。

> 同一个组合不要同时开两个窗口监听，后开的会顶掉前一个的 `listenKey`。

## 八、数据落盘

目录：`bot\data\`，按天切分，每行一个 JSON。

| 文件 | 内容 |
|---|---|
| `events-YYYYMMDD.jsonl` | 每笔成交：`portfolio` / `nickname` / `lead` / `latency_ms` / 原始 `o` |
| `raw-YYYYMMDD.jsonl` | 全部原始 WS 报文（含 `ACCOUNT_UPDATE`、`listenKeyExpired`） |
| `bot.log` | 进程日志（仅 `start.bat` 启动时产生） |

快速看今天的成交：

```powershell
Get-Content bot\data\events-$(Get-Date -Format yyyyMMdd).jsonl |
  ConvertFrom-Json |
  Select-Object @{n='time';e={[DateTimeOffset]::FromUnixTimeMilliseconds($_.recv).LocalDateTime}},
                nickname, @{n='sym';e={$_.o.s}}, @{n='side';e={$_.o.S}},
                @{n='qty';e={$_.o.l}}, @{n='px';e={$_.o.ap}}, @{n='rp';e={$_.o.rp}}, latency_ms
```

## 九、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动即退出，提示 `missing session.json` | 没生成会话 | 执行第五节 |
| 提示 `telegram not configured` | token / chat_id 为空 | 检查 `.env`，注意不要留空格 |
| 一个 `connected` 都没有 | cookie 过期 / 网络不通 | 重新抓会话；确认能访问 `fstream.binance.com` |
| 部分组合连不上 | 该组合可能已停止跟单 | 看 `detail-list` 的 `status` |
| 连上了但一直没消息 | 带单员没交易，或组合已空仓停跟 | 属正常，等成交 |
| 收不到 Telegram，但有 `FILL` 日志 | 代理问题或被机器人拉黑 | 配 `TELEGRAM_PROXY`，或给机器人发条消息解锁 |
| 消息延迟几百毫秒以上 | Telegram 网络慢 | 配代理；本地处理只占几毫秒 |
| 新增跟单没被监听 | 组合是启动时发现的 | 重启一次 |
| 收到「⚠️ 监听中断」 | cookie 过期 | 重新执行第五节 |

## 十、安全

1. **`TELEGRAM_BOT_TOKEN` 曾经明文提交在公开仓库**（`Binance-Join-CopyTrader-Automation`）。
   建议去 BotFather `/revoke` 重新生成，再替换 `.env`。
2. **`session.json` 等同账号登录态**，能下单、能提币（取决于账号设置）。
   只在本地跑，不要放云服务器，不要在聊天里贴。
   用完可以在币安 App「退出所有设备」使其全部失效。
3. `.env` 和 `session.json` 都已在 `.gitignore`，确认 `git status` 里看不到它们。
4. 建议给币安账号开启二次验证，并单独设置 API Key 的 IP 白名单（本程序不需要 API Key，只需要网页会话）。

## 十一、已知限制

| 限制 | 说明 |
|---|---|
| 只推成交 | 不推挂单/撤单；成交以实际 fill 为准 |
| 只覆盖"你的组合" | 拿到的是镜像成交，不是带单员原始仓位 |
| 组合变动需重启 | 启动时发现组合，运行中新跟/取消跟单不会自动生效 |
| 依赖网页会话 | 2–3 天要更新一次，接口改版可能失效 |
| 高频带单员会刷屏 | 每笔成交一条；需要的话可加"同币种 N 秒合并" |
| 非官方接口 | 属于对网页私有接口的自动化访问，有账号风险 |

## 附录 A：金额字段与开仓比例

### A.1 三个金额别搞混

| 字段（`detail-list`） | 含义 | 你账户的实测值 |
|---|---|---|
| `netCopyAmount` | **净投入本金**（跟单至今净入金） | 200.00 / 88.50 / 92.87 / 142.01 |
| `marginBalance` | **保证金余额** = 净投入 + 已实现 + 未实现 | 200.26 / 100.08 / 100.24 / 200.95 |
| `realizedPnl` | 已实现盈亏 | 0.26 / 11.58 / 7.36 / 58.95 |
| `unrealizedPnl` | 未实现盈亏 | 当前均为 0 |

实测恒等式：`marginBalance = netCopyAmount + realizedPnl + unrealizedPnl`。

### A.2 开仓比例应该用什么当基数

**用 `marginBalance`（保证金余额/净值），不是 `netCopyAmount`。**
因为账户能开多大仓，取决于当前净值（已实现盈亏已经改变了下单能力），
用净投入会低估或高估。

公式（净值比模式）：

```
目标名义 = 带单员该仓位名义 × (我的 marginBalance / 带单员 marginBalance) × 系数
手数     = 目标名义 / 当前价格
```

带单员的 `marginBalance` 可以从带单员详情接口拿到，例如：

| 带单员 | 带单员 marginBalance |
|---|---|
| 玄冥二老 | 7,320.66 |
| 星辰社区-双子星 | 2,078.89 |
| 星辰社区-海 | 6,404.02 |
| 星辰社区-意钦 | 20,186.94 |

### A.3 还差一个字段：可用余额

`marginBalance` **不等于**能开多少仓——已有持仓会占用保证金。
真正下单前必须用 `availableBalance` 校验（来自
`POST /bapi/futures/v6/private/future/user-data/user-balance`，每个组合一条）。

计划中的下单前检查：

```
可用保证金 ≥ 目标名义 / 杠杆 × (1 + 缓冲)
```

### A.4 当前状态

GUI 已改成同时显示「净投入 / 保证金余额 / 已实现盈亏」。
右侧「开仓比例」等参数仍是占位，等交易 API 接入后再按 A.2 的公式实现。

## 附录 B：WebSocket 排查

### B.1 现象

监听器显示 `connected [xxx]`，TCP 也是 Established，但成交后**收不到任何推送**，
`bot/data/raw-YYYYMMDD.jsonl` 一条记录都没有。

### B.2 根因（2026-11-11 实测修正）

币安把合约用户数据流改成了**新路径 + 显式订阅**：

| 项 | 旧写法（已失效） | 新写法（正确） |
|---|---|---|
| 地址 | `wss://fstream.binance.com/ws/<listenKey>` | `wss://fstream.binance.com/private/stream` |
| 订阅 | 路径里带 listenKey，自动订阅 | 连上后发 `{"method":"SUBSCRIBE","params":["<listenKey>"],"id":1}` |
| 报文 | 事件裸 JSON | `{"stream":"<listenKey>","data":{...事件...}}` |
| 行情 | `/ws/btcusdt@aggTrade` | `/market/stream` + 同样方式 SUBSCRIBE |

旧写法**不会报错**：TCP 能连、TLS 能握手、WebSocket 能升级，但永远不下发数据。
排查时极易误判成“代理或节点问题”。

### B.3 怎么判断通没通

订阅成功会先收到一条回执：

```json
{"result":null,"id":1}
```

收到回执说明通道正常，接着只是等事件。之后的事件形如：

```json
{"stream":"<listenKey>","data":{"e":"ORDER_TRADE_UPDATE","o":{...}}}
```

`bot/data/raw-YYYYMMDD.jsonl` 里能看到这两种报文。

### B.4 排查顺序

1. `raw-*.jsonl` 里有没有 `{"result":null,"id":1}` —— 没有就是订阅没发出去
2. 有回执但没事件 —— 看 `data.e` 是不是 `ORDER_TRADE_UPDATE`、`o.x` 是不是 `TRADE`
3. 用 `python probe\probe_newpaths.py` 测公共行情流：
   `market/stream + SUBSCRIBE` 能出数据，说明传输没问题，问题在订阅参数


## 附录 C：执行账户密钥放哪

执行账户的 API Key / Secret 现在**只存在 `.env`**：

```
EXEC_API_KEY=xxxxxxxx
EXEC_API_SECRET=yyyyyyyy
```

- GUI 的「仓位复制 → 执行账户」填完点保存，会自动写进 `.env`
- `gui/copy_config.json` 里不再保存明文密钥
- 旧版本存在 JSON 里的密钥，打开 GUI 会自动迁移到 `.env` 并删除
- `.env` 已在 `.gitignore` 里，不会进仓库
